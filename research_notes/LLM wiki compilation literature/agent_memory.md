# LLM Agent Memory Systems with a Persistent, Self-Edited Knowledge Store ("the LLM maintains its own wiki")

Scope note: compiled 2026-11-07 for WiCER (arXiv 2605.07068). **Verification legend:** [V] means I read the arXiv abstract (via the arXiv API) or the paper HTML in this session. [V-html] means I also read result sections of the paper. [S] means secondhand (blog, search summary, or my prior knowledge not re-checked here). The arXiv IDs below are only ones that the arXiv API resolved to the stated title. Abstract tails were cut off in my fetch for a few papers. Numbers marked "(S)" inside a [V] item come from memory, not from the text I read.

## Q1. Core systems: how is memory written, consolidated, updated, and linked? (MemGPT/Letta, A-MEM, Mem0, MemoryOS, MemOS, Zep, MIRIX, Cognitive Weave, sleep-time compute, Generative Agents, ReadAgent, MemWalker, 2025–26 successors including "LLM Wiki" systems)

### Takeaway
Up to 2025, agent-memory systems mostly write **LLM-extracted, abstracted units** (facts, notes, summaries, graph triples) and run some form of consolidation (ADD/UPDATE/DELETE, reflection, tiered promotion, offline "sleep-time" rewriting). In 2026 the field moved toward (a) the **"LLM Wiki" pattern**: an LLM compiles sources into interlinked markdown pages and maintains them with ingest/query/lint operations, and (b) **immutable verbatim stores with provenance links**, where the abstracted layer is treated as an index or cache rather than the source of truth. Several 2026 wiki systems already close the loop with downstream-query feedback (Error Book, WikiLoop, DeepRefine). These are WiCER's nearest neighbours.

### Cited Findings

**Foundational (2023–2024)**
- [V] **MemGPT: Towards LLMs as Operating Systems**, Packer, Wooders, Lin, Fang, Patil et al., arXiv 2310.08560 (2023). "Virtual context management" modelled on OS memory hierarchies. The LLM moves data between in-context (main) memory and external (archival/recall) tiers through function calls, and uses interrupts for control flow. Evaluated on document analysis beyond the context window and on multi-session chat. This is the origin of Letta's self-edited "memory blocks". Relevance to WiCER: in-context core memory that the agent edits itself is the in-context-wiki analogue. — [arXiv](https://arxiv.org/abs/2310.08560)
- [V] **Generative Agents: Interactive Simulacra of Human Behavior**, Park, O'Brien, Cai, Morris, Liang et al., arXiv 2304.03442 (UIST 2023). Stores a complete natural-language memory stream, periodically synthesizes higher-level **reflections**, and retrieves by recency, importance and relevance. The original "abstract upward, keep raw below" design. — [arXiv](https://arxiv.org/abs/2304.03442)
- [V] **Walking Down the Memory Maze (MemWalker)**, H. Chen, Pasunuru, Weston, Celikyilmaz, arXiv 2310.05029 (2023). Builds a tree of summary nodes over a long text. At query time the LLM navigates the tree. Beats long-context, recurrence and retrieval baselines on long-text QA. — [arXiv](https://arxiv.org/abs/2310.05029)
- [V] **ReadAgent: A Human-Inspired Reading Agent with Gist Memory of Very Long Contexts**, K.-H. Lee, X. Chen, Furuta, Canny, Fischer, arXiv 2402.09727 (ICML 2024). (1) Paginates text into episodes, (2) compresses each episode into a short **gist**, (3) **looks up the original passages** when details are needed. Raises effective context 3.5–20x and beats retrieval, full-context and gist-only baselines on QuALITY, NarrativeQA and QMSum. Key pattern: gist plus a pointer back to the verbatim text. — [arXiv](https://arxiv.org/abs/2402.09727)
- [V] **Recursively Summarizing Enables Long-Term Dialogue Memory**, Q. Wang et al., arXiv 2308.15022 (2023). Repeatedly rewrites memory as f(previous memory, new context). This is the "iterative rewriting" design that later work blames for detail erosion (see ACE below). — [arXiv](https://arxiv.org/abs/2308.15022)
- [V] **MemTree: Dynamic Tree Memory Representation**, Rezazadeh, Li, Wei, Bao, arXiv 2410.14052 (2024). An online tree whose nodes hold aggregated text at increasing abstraction. New information is inserted by embedding comparison, and parent nodes are re-summarized. — [arXiv](https://arxiv.org/abs/2410.14052)
- [V] **THEANINE: Timeline-based Memory Management**, Ong et al., arXiv 2406.10996 (NAACL 2025). Argues *against* deleting outdated memories: it links memories by temporal and causal relations into timelines and never removes them. — [arXiv](https://arxiv.org/abs/2406.10996)

**2025 production and academic memory systems**
- [V] **A-MEM: Agentic Memory for LLM Agents**, W. Xu, Liang, Mei, Gao, Tan et al., arXiv 2502.12110 (2025; NeurIPS 2025 per repo [S]). Zettelkasten-style. Each new memory becomes a structured **note** (context description, keywords, tags). The LLM finds related notes and adds **links**, and **memory evolution** lets new notes rewrite the attributes of old ones. Relevance: a self-linking note store, with LLM rewriting of existing entries as the consolidation step. — [arXiv](https://arxiv.org/abs/2502.12110)
- [V] **Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory**, Chhikara, Khant, Aryan, Singh, Yadav, arXiv 2504.19413 (2025). Two phases. Extraction: an LLM extracts salient facts. Update: for each fact, the LLM picks ADD/UPDATE/DELETE/NOOP against similar existing memories. Mem0^g adds a graph variant. Reports +26% relative on LLM-as-judge versus OpenAI memory on LoCoMo, and graph memory about 2% above base Mem0. (S) It also claims about 91% lower p95 latency and >90% token savings versus full context. — [arXiv](https://arxiv.org/abs/2504.19413). The comparison is disputed: Letta reports a plain filesystem agent at 74.0% on LoCoMo (gpt-4o-mini) versus Mem0's reported 68.5% for its best graph variant, and says Mem0 did not clarify its methodology — [Letta blog](https://www.letta.com/blog/benchmarking-ai-agent-memory) [S]
- [V] **Zep: A Temporal Knowledge Graph Architecture for Agent Memory**, Rasmussen, Paliychuk, Beauvais, Ryan, Chalef, arXiv 2501.13956 (2025). The Graphiti engine builds a **bi-temporal KG** (episodes → entities/facts → communities) that keeps historical relationships rather than overwriting them. Reports 94.8% vs 93.4% (MemGPT) on DMR, and up to +18.5% accuracy with 90% lower latency on LongMemEval. — [arXiv](https://arxiv.org/abs/2501.13956)
- [V] **MemoryOS (Memory OS of AI Agent)**, Kang, Ji, Zhao, Bai, arXiv 2506.06326 (EMNLP 2025 [S]). Three tiers: short-term, mid-term and long-term personal memory. Short→mid promotion uses dialogue-chain FIFO, and mid→long uses segmented "pages" with heat scores. Reports +49.11% F1 and +46.18% BLEU-1 over baselines on LoCoMo with GPT-4o-mini. — [arXiv](https://arxiv.org/abs/2506.06326)
- [V] **MemOS: An Operating System for Memory-Augmented Generation**, Z. Li, S. Song, H. Wang et al., arXiv 2505.22101 (2025), and **MemOS: A Memory OS for AI System**, Z. Li, Xi, C. Li et al., arXiv 2507.03724 (2025). Unify plaintext, activation (KV-cache) and parametric memory under a "MemCube" abstraction with lifecycle, provenance and migration between types. Relevance: the explicit **plaintext ↔ KV-cache memory** migration is architecturally close to WiCER's compile-then-KV-cache serving. — [arXiv 2505.22101](https://arxiv.org/abs/2505.22101); [arXiv 2507.03724](https://arxiv.org/abs/2507.03724)
- [V] **MIRIX: Multi-Agent Memory System for LLM-Based Agents**, Yu Wang, Xi Chen, arXiv 2507.07957 (2025). Six typed memories (Core, Episodic, Semantic, Procedural, Resource, Knowledge Vault), each managed by its own agent. On ScreenshotVQA it scores +35% over RAG with 99.9% less storage. (S) It reports 85.4% on LoCoMo. — [arXiv](https://arxiv.org/abs/2507.07957)
- [V] **Cognitive Weave**, Vishwakarma et al., arXiv 2506.08098 (2025). A "spatio-temporal resonance graph" of insight particles with a "cognitive refinement" step that synthesizes cluster-level "insight aggregates". Reports a 34% average task-completion improvement. The terminology is heavy and the evidence is weak; treat as low-weight. — [arXiv](https://arxiv.org/abs/2506.08098)
- [V] **Sleep-time Compute: Beyond Inference Scaling at Test-time**, K. Lin, Snell, Y. Wang, Packer, Wooders et al. (Letta/UC Berkeley), arXiv 2504.13171 (2025). Offline "thinking" over a context *before* queries arrive (in Letta, a sleep-time agent rewrites memory blocks). About 5x less test-time compute for equal accuracy on Stateful GSM-Symbolic/AIME. Scaling sleep-time compute adds +13%/+18%. Amortizing over related queries cuts per-query cost 2.5x. Efficacy correlates with **query predictability**. Relevance: WiCER's compile step is sleep-time compute, and the predictability finding bears on probe-to-held-out generalization. — [arXiv](https://arxiv.org/abs/2504.13171)
- [V] **LightMem**, Fang et al., arXiv 2510.18866 (2025). Atkinson–Shiffrin-style pipeline: sensory filter/compression → topic-grouped short-term memory → long-term memory with an **offline "sleep-time" update** that decouples consolidation from online inference. — [arXiv](https://arxiv.org/abs/2510.18866)
- [V] **Nemori: What Deserves Memory: Adaptive Memory Distillation**, W. Ma et al., arXiv 2508.03341 (2025). Episodic narratives plus semantic distillation driven by **prediction error**: it stores what the current memory fails to predict. Close in spirit to WiCER's "store what the probes show is missing". — [arXiv](https://arxiv.org/abs/2508.03341)
- [V] **PREMem: Pre-Storage Reasoning for Episodic Memory**, S. Kim et al., arXiv 2509.10852 (2025). Moves reasoning to write time (fragments typed as factual, experiential or subjective, plus cross-session evolution links), so that **small readers** match larger baselines. Directly relevant to WiCER's "big compiler, small reader" split. — [arXiv](https://arxiv.org/abs/2509.10852)
- [V] **SeCom: On Memory Construction and Retrieval for Personalized Conversational Agents**, Pan, Wu, Jiang et al., arXiv 2502.05589 (ICLR 2025). Turn-level, session-level and summary-based memory units **each** have accuracy and quality limits. Topical segments plus LLMLingua-2 denoising work best. — [arXiv](https://arxiv.org/abs/2502.05589)
- [V] **Agent Workflow Memory**, Z. Z. Wang, Mao, Fried, Neubig, arXiv 2409.07429 (2024): induces reusable workflows (+24.6% Mind2Web, +51.1% WebArena relative). [V] **Dynamic Cheatsheet**, Suzgun, Yuksekgonul, Bianchi, Jurafsky et al., arXiv 2504.07952 (2025): an evolving test-time memory of strategies (GPT-4o Game of 24 goes from 10% to 99%). [V] **ReasoningBank**, Ouyang et al., arXiv 2509.25140 (2025): distills strategies from self-judged successes and failures. These are procedural memories, not fact stores. — [AWM](https://arxiv.org/abs/2409.07429); [DC](https://arxiv.org/abs/2504.07952); [ReasoningBank](https://arxiv.org/abs/2509.25140)
- [V] **ACE: Agentic Context Engineering**, Q. Zhang, C. Hu et al., arXiv 2510.04618 (2025). Names two failure modes of self-rewritten contexts: **"brevity bias"** (insights dropped for concise summaries) and **"context collapse"** (iterative rewriting erodes details over time). The fix is **structured, incremental delta updates** (generator → reflector → curator) instead of full rewrites. +10.6% on agents and +8.6% on finance. **Highly relevant to WiCER**: recompiling the wiki from scratch each iteration is the collapse-prone design, and itemized deltas are the alternative. — [arXiv](https://arxiv.org/abs/2510.04618)
- [V] **HippoRAG 2: From RAG to Memory**, Gutiérrez et al., arXiv 2502.14802 (ICML 2025 [S]). Structure-augmented RAG used to fall below plain RAG on simple factual memory. HippoRAG 2 fixes this with deeper passage integration, i.e. it keeps the passages and does not rely on the graph alone. — [arXiv](https://arxiv.org/abs/2502.14802)

**2026: the "LLM Wiki" pattern and verbatim-anchored memory**
- [S] **Karpathy, "LLM Wiki" gist (2026)**. An LLM incrementally builds and maintains interlinked markdown pages from raw sources. Three layers (sources → wiki → schema file such as CLAUDE.md/AGENTS.md) and three operations (**ingest, query, lint**). Good answers are filed back into the wiki, and "lint" passes look for contradictions and gaps. I did not open the primary gist ([gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)). Details come from secondary write-ups, e.g. [ronancodes summary](https://ronancodes.github.io/llm-wiki/docs/research/karpathy/) and [pixelbrix note](https://pixelbrix-site.pages.dev/notes/the-llm-knowledge-base/).
- [V] **WiCER: Wiki-memory Compile, Evaluate, Refine**, Juan M. Huerta, arXiv 2605.07068 (2026). The target paper. Blind compilation fails (2.14–2.32 vs 3.46 for RAG; 53–60% catastrophic failure). A CEGAR-style probe loop recovers 80% of lost quality in 1–2 iterations (3.24 vs 3.47 raw full-context) and cuts catastrophic failures by 55% relative. — [arXiv](https://arxiv.org/abs/2605.07068)
- [V] **Streaming Knowledge Compilation: Proactive Materiality-Scored Pinning for Time-Evolving LLM Wikis**, Juan M. Huerta, arXiv 2606.09877 (2026). Same author as WiCER. Streaming wiki under a fixed token budget, with pinning by a "materiality" score before queries arrive. Proves an O(√(T log K)) regret bound. Reports a pervasive **LLM-as-judge confound on post-training knowledge** and argues that regret, not absolute QA score, is the reliable metric. — [arXiv](https://arxiv.org/abs/2606.09877)
- [V] **LLM-Wiki: Retrieval as Reasoning: Self-Evolving Agent-Native Retrieval via LLM-Wiki**, Ming, F. Li, X. Wu, Que, arXiv 2605.25480 (2026). Compiles documents into wiki pages with bidirectional links, exposes search/read/follow-link tools, and adds an **"Error Book" for persistent structural and semantic self-correction**. +2.0–8.1 F1 over HippoRAG 2, LightRAG and GraphRAG on HotpotQA, MuSiQue and 2Wiki. Best on AuthTrace. — [arXiv](https://arxiv.org/abs/2605.25480)
- [V] **WikiLoop: Jointly Learning to Build and Navigate Agent-Native Wikis with Downstream Feedback**, Ming, F. Li, Que, arXiv 2607.26604 (2026). A Builder proposes wiki edits, and a frozen Navigator scores each edit by its **change in downstream answer quality**, with a **guard penalty against regressions on unrelated queries**. Learned edits **remain useful to a held-out Navigator**. Qwen3.5-9B reaches 62.6 Answer Correctness on AuthTrace (+6.3 over LLM-Wiki base). This is the closest RL analogue of WiCER's repair loop, and it includes an explicit anti-regression term. — [arXiv](https://arxiv.org/abs/2607.26604)
- [V] **DeepRefine: Agentic Knowledge Refinement via Reinforcement Learning**, H. Huang, Bai, S. Liu, Y. Wang et al., arXiv 2605.10488 (2026). RL agent that refines a pre-built KG or **LLM-Wiki** using user queries: it diagnoses defects (missing evidence or links, imprecise claims, coreference), then makes targeted incremental edits. Uses a "Gain-Beyond-Draft" reward. The abstract gives no numbers beyond "consistent gains". — [arXiv](https://arxiv.org/abs/2605.10488)
- [V] **TrajWiki: Source-Grounded Memory Trajectories**, J. Sun et al., arXiv 2608.00967 (2026). Each memory is an **immutable snapshot trajectory** with claim-level ADD/REVISE/DEPRECATE. A "Memory Wiki" layer of interlinked pages routes queries wiki page → trajectory → source message. Evaluated on LoCoMo and MedMT. — [arXiv](https://arxiv.org/abs/2608.00967)
- [V] **WFM: Wiki Foundation Model**, Dong, Luo et al., arXiv 2609.18182 (2026). Learns graph-style encodings over LLM-Wiki markdown with link topology. Mostly a retrieval and infra contribution. — [arXiv](https://arxiv.org/abs/2609.18182)
- [V] **Knowledge Compounding (Agentic ROI)**, Wen, Ku, arXiv 2604.11243 (2026). Reference implementation of Karpathy's pattern. 4 sequential queries consume 47K tokens versus 305K for RAG (−84.6%). Very small N, so this is cost evidence only. — [arXiv](https://arxiv.org/abs/2604.11243)
- [V] **Memory as Metabolism**, Miteski, arXiv 2604.12034 (2026). Design and position paper on single-user LLM wikis. Names **entrenchment / Kuhnian ossification** as a wiki failure mode and proposes TRIAGE/DECAY/CONTEXTUALIZE/CONSOLIDATE/AUDIT operations. It also lists "MemPalace" and "LLM Wiki v2" as April 2026 wiki proposals. No experiments. — [arXiv](https://arxiv.org/abs/2604.12034)
- [V] **TierMem: From Lossy to Verified: A Provenance-Aware Tiered Memory**, Q. Zhu et al., arXiv 2602.17913 (2026). Names the **"write-before-query barrier"**: summaries drop details that a later query hinges on. Uses a summary index plus an immutable raw log, with a sufficiency router that escalates to raw, then **writes back verified findings as summary units linked to raw sources**. LoCoMo: 0.851 versus 0.873 for raw-only, with 54.1% fewer tokens. — [arXiv](https://arxiv.org/abs/2602.17913)
- [V] **True Memory: Storage Is Not Memory**, Adler, Zehavi, arXiv 2605.04897 (2026). "Extraction at ingestion is the wrong primitive". Verbatim events plus a multi-stage retrieval pipeline. Reports LoCoMo 93.0% versus Mem0 61.4% and Zep ~71% (gpt-4.1-mini reader), LongMemEval 87.8%, and BEAM-1M 76.6%. Vendor paper. — [arXiv](https://arxiv.org/abs/2605.04897)
- [V] **FlexA-Mem: Budget-Adaptive Agentic Memory**, W. Xu (A-MEM author), Han, Zhu, Q. Zhang (ACE author) et al., arXiv 2610.33274 (2026). Writes each unit once into an **immutable store** and renders a fresh, budgeted memory per call (timeline plus raw excerpts, no LLM call). States that "**summaries drop exact strings**". On LongMemEval and LoCoMo it matches a keyword retriever that writes no memory, "while memories built on text written by an LLM fall far behind at tight budgets". Notable as A-MEM's own authors moving toward verbatim storage. — [arXiv](https://arxiv.org/abs/2610.33274)
- [V] **Schema-Grounded Memory**, Petrov et al., arXiv 2604.27906 (2026). Argues the opposite: production memory needs a system of record (exact facts, updates, deletions, explicit unknowns). Uses an iterative schema-aware write path with validation gates and retries. 90.42% object-level extraction accuracy. — [arXiv](https://arxiv.org/abs/2604.27906)
- [V] **Event-centric EDU memory: A Simple Yet Strong Baseline for Long-Term Conversational Memory**, S. Zhou, J. Han, arXiv 2511.17208 (2025). Explicitly **non-compressive**: decomposes sessions into self-contained elementary discourse units with source-turn attribution, rather than summaries or triples. — [arXiv](https://arxiv.org/abs/2511.17208)
- [V] **Memori**, Borro et al., arXiv 2603.19935 (2026). Counterpoint favouring compact structure: semantic triples plus summaries give 81.95% on LoCoMo at 1,294 tokens/query (~5% of full context). Vendor paper. — [arXiv](https://arxiv.org/abs/2603.19935)
- [V] **Survey: Memory in the Age of AI Agents**, Hu, Liu, Yue, G. Zhang et al., arXiv 2512.13564 (2025). Taxonomy of forms (token-level, parametric, latent), functions and dynamics. Distinguishes agent memory from RAG and context engineering. — [arXiv](https://arxiv.org/abs/2512.13564)

### Inferences
- WiCER's design (compile → evaluate with probes → force preservation) appears to be one point in a 2026 cluster of "LLM-Wiki with feedback" systems: Error Book (LLM-Wiki), WikiLoop, DeepRefine and TrajWiki. WiCER's distinguishing features look like **in-context or KV-cache serving to a small reader**, with no retrieval, and a **CEGAR framing**. LLM-Wiki, WikiLoop and DeepRefine serve the wiki through tool-based navigation instead.
- WikiLoop's guard penalty for regressions on unrelated queries, plus its held-out-Navigator check, map directly onto WiCER's measured held-out displacement problem (pinned docs gain, unpinned docs lose).
- ACE's "context collapse" and TierMem's "write-before-query barrier" give WiCER citable names for its blind-compilation failure.

- I did not verify MemoryOS, A-MEM or HippoRAG 2 venue claims, or the MIRIX 85.4% LoCoMo figure (abstract cut off).
- "MemPalace" and "LLM Wiki v2" are mentioned only secondhand (Miteski; search results). I found no arXiv paper for them.

## Q2. Learned memory writing (RL-trained memory agents) and self-improving / test-time knowledge editing

### Takeaway
Since mid-2025, RL is the standard way to *learn* what to write. The reward is downstream QA accuracy over the memory. Training sets can be tiny (Memory-R1: 152 QA pairs), and some of these papers report generalization across benchmarks and lengths. The 2026 wiki-specific RL work (WikiLoop, DeepRefine) adds anti-regression and held-out-reader checks. Weight-update analogues (SEAL, Active Reading, EntiGraph) show that *self-generated restatements and questions* about a corpus drive knowledge uptake.

### Cited Findings
- [V] **MemGPT-style ops learned with RL: Memory-R1**, Yan, Yang, Huang, Nie, Ding et al., arXiv 2508.19828 (2025). A Memory Manager learns ADD/UPDATE/DELETE/NOOP, and an Answer Agent filters memories. Both are trained with PPO/GRPO using **outcome reward only**. With **152 training QA pairs** it beats baselines and generalizes across LoCoMo, MSC, LongMemEval and 3B–14B scales. — [arXiv](https://arxiv.org/abs/2508.19828)
- [V] **MEM1**, Zhou, Qu, Wu, Kim, Prakash et al., arXiv 2506.15841 (2025). End-to-end RL with a **constant-size internal state** that is rewritten each turn (consolidate plus discard). MEM1-7B scores 3.5x higher with 3.7x less memory than Qwen2.5-14B-Instruct on 16-objective multi-hop QA, and generalizes beyond the training horizon. — [arXiv](https://arxiv.org/abs/2506.15841)
- [V] **MemAgent**, H. Yu, T. Chen, Feng, J. Chen, Dai et al., arXiv 2507.02259 (2025). Reads text in segments and **overwrites** a fixed-length memory. Trained with multi-conversation DAPO. Trained at 8K context on 32K text, it extrapolates to 3.5M-token QA with <5% loss and scores 95%+ on RULER-512K. Shows learned overwrite memory can be faithful enough for long-document QA. — [arXiv](https://arxiv.org/abs/2507.02259)
- [V] **Mem-α: Learning Memory Construction via RL**, Yu Wang (MIRIX/MemoryAgentBench) et al., arXiv 2509.25911 (2025). Trains an agent to manage a multi-component memory (core/episodic/semantic) chunk by chunk. Reward is QA accuracy over the full interaction history. (S) Generalizes to >13x longer inputs than seen in training. — [arXiv](https://arxiv.org/abs/2509.25911)
- [V] **WikiLoop** (Q1) and **DeepRefine** (Q1) are RL over wiki edits with a downstream-utility reward. DeepRefine's "Gain-Beyond-Draft" reward credits only improvement over the draft knowledge base. — [WikiLoop](https://arxiv.org/abs/2607.26604); [DeepRefine](https://arxiv.org/abs/2605.10488)
- [V] **SEAL: Self-Adapting Language Models**, Zweiger, Pari, Guo, Akyürek et al., arXiv 2506.10943 (2025). The model writes "self-edits" (restatements and implications of a passage) and fine-tunes on them, with RL on downstream accuracy after the update. Knowledge-incorporation experiments. A weight-space analogue of "rewrite the corpus so that it gets learned". — [arXiv](https://arxiv.org/abs/2506.10943)
- [V] **Synthetic Continued Pretraining (EntiGraph)**, Z. Yang, Band, S. Li, Candès et al., arXiv 2409.07431 (ICLR 2025 [S]). Synthesizes diverse entity-relation text from a small corpus so it can be learned parametrically. — [arXiv](https://arxiv.org/abs/2409.07431)
- [V] **Active Reading**, J. Lin et al. (Meta), arXiv 2508.09494 (2025). The model studies material with self-generated learning strategies. 66% on a SimpleQA-Wiki subset (+313% relative over vanilla finetuning) and 26% on FinanceBench (+160%). — [arXiv](https://arxiv.org/abs/2508.09494)
- [V] **"Language Models Need Sleep"**, Behrouz, Hashemi, Javanmard, Mirrokni, arXiv 2606.03979 (2026). Consolidation (distill short-term memory into long-term weights) plus "Dreaming" (RL-generated synthetic rehearsal curriculum). — [arXiv](https://arxiv.org/abs/2606.03979)
- [V] **GEPA**, Agrawal et al., arXiv 2507.19457 (2025). Reflective natural-language prompt evolution beats GRPO by 6% on average (up to 20%) with up to 35x fewer rollouts. Relevance: text-space optimization of an artifact from a few rollouts, which is structurally the same as probe-driven wiki repair. — [arXiv](https://arxiv.org/abs/2507.19457)

### Inferences
- The RL memory-writing papers all optimize *what to keep* against QA reward over the whole history. WiCER's probe loop is a non-gradient, single-instance version: probes act as the reward and pinning acts as the policy update. Memory-R1's 152-example result suggests a small probe set can carry signal. Whether it carries signal *to unseen questions* is the open issue (Q4).
- A cheap WiCER extension would be a Gain-Beyond-Draft-style acceptance rule: keep an edit only if it beats the previous wiki on probes **and** on a guard set.

### Gaps
- I did not read results sections for Mem-α, SEAL or WikiLoop. Their held-out and generalization numbers come from abstracts only.
- I found no RL-trained memory writer evaluated specifically on *faithfulness of the written store* (hallucinated or unsupported content in memory), as opposed to downstream QA.

## Q3. Benchmarks and what they say about abstraction vs raw storage

### Takeaway
Across LongMemEval, MemoryAgentBench, independent head-to-heads and the 2026 verbatim-store papers, the evidence consistently says that **storing LLM-extracted facts or summaries in place of raw text loses detail-level recall**. Raw chunks with BM25 or long context beat Mem0, Cognee, Zep and GraphRAG on accurate retrieval. Abstractions help mainly as **keys/indexes** (LongMemEval's K = V + fact), for **multi-session aggregation**, and for **token cost**. Benchmark validity is itself shaky: label errors, reasoning confounds, scoring-target dependence and vendor disputes.

### Cited Findings
- [V-html] **LongMemEval**, D. Wu, H. Wang, W. Yu, Y. Zhang, K.-W. Chang et al., arXiv 2410.10813 (ICLR 2025). 500 questions over 5 abilities: extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention. Long-context reading of the ~115k-token history drops accuracy sharply. GPT-4o goes from 0.870 (oracle sessions) to 0.606 (full history), a 30.3% drop. Llama 3.1 70B goes from 0.744 to 0.334 (−55.1%). ChatGPT memory scores 0.577 versus 0.918 offline. **Value granularity**: replacing sessions or rounds with *extracted summaries or facts as values generally hurt QA because of information loss*. The exception is multi-session reasoning, where fact values helped. **Key expansion** (key = raw value + extracted facts) gave +9.4% recall@k and +5.4% accuracy on average, e.g. round-level top-5 recall from 0.582 to 0.644. Condensed-only keys did not help. Llama 3.1 8B degrades beyond ~3k retrieved tokens, while GPT-4o keeps improving past 20k. — [arXiv](https://arxiv.org/abs/2410.10813)
- [V] **LoCoMo**, Maharana, D.-H. Lee, Tulyakov, Bansal, Barbieri et al., arXiv 2402.17753 (ACL 2024). Conversations average ~300 turns and ~9K tokens, spanning up to 35 sessions. QA, event summarization and multimodal tasks. Long-context and RAG help, but models still lag humans. — [arXiv](https://arxiv.org/abs/2402.17753)
- [V-html] **MemoryAgentBench (Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions)**, Hu, Yu Wang, McAuley, arXiv 2507.05257 (2025; ICLR 2026 [S]). Four competencies: accurate retrieval (AR), test-time learning (TTL), long-range understanding (LRU), selective forgetting (FactConsolidation). Results from Table 3:
  - AR: GPT-5-mini long context 74.4, HippoRAG-v2 65.1, **BM25 60.5**, and embedding RAG ~54–55, versus **Mem0 32.6, Cognee 28.3, Zep 37.5, GraphRAG 40.9, MemGPT 34.3**. MIRIX scores 47.5, rising to 63.0 with a GPT-4.1-mini backbone. EventQA: GPT-4o 77.2, BM25 74.6, Mem0 37.5.
  - LRU: long context 62–66, best RAG 36.2, Mem0 20.7.
  - Selective forgetting: all methods ≤28% on multi-hop. Mem0 averages 10.0.
  - Smaller chunks help AR but hurt LRU.
  - The paper does not *explicitly* frame these results as abstraction versus raw storage. That reading is mine (see Inferences). — [arXiv](https://arxiv.org/abs/2507.05257)
- [V] **Fact-based memory vs long context (Bricks)**, Pollertlam, Kornsuwannawit, arXiv 2603.04814 (2026). Mem0-based memory versus long-context GPT-5-mini. **Long context has higher factual recall on LongMemEval and LoCoMo**. Memory is competitive only on PersonaMem v2, which rests on stable persona attributes. Memory becomes cheaper after about 10 turns at 100k context. — [arXiv](https://arxiv.org/abs/2603.04814)
- [V] **TierMem** (raw-only 0.873 > summary-plus-escalation 0.851 on LoCoMo), **True Memory** (verbatim 93.0% vs Mem0 61.4%), and **FlexA-Mem** ("memories built on text written by an LLM fall far behind at tight budgets") all point the same way. See Q1 for citations. — [TierMem](https://arxiv.org/abs/2602.17913); [True Memory](https://arxiv.org/abs/2605.04897); [FlexA-Mem](https://arxiv.org/abs/2610.33274)
- [S] **Letta filesystem baseline**: a gpt-4o-mini agent with grep/search over the raw LoCoMo transcript scores 74.0%, versus 68.5% reported for Mem0^g. — [Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory)
- [V] **Scoring-target dependence: Same Ranking, Different Winner**, Panthi, Abdelfattah, arXiv 2605.24060 (2026). When derived memories (facts, summaries) coexist with source turns, whether the scorer credits the Raw, Source or Canonical form changes nDCG on 83.4–94.0% of queries. It **flips orderings for Mem0 and MemoryOS** and reverses parser-density recommendations. Relaxed source-linked credit was justified only 29.2% of the time. — [arXiv](https://arxiv.org/abs/2605.24060)
- [S] **Benchmark-quality critiques**: a search summary reports that LoCoMo and LongMemEval mix memory with non-trivial reasoning and have reported label errors (from the community "Field Guide to AI Memory"). Not a primary source. — [memoryplugin field guide](https://www.memoryplugin.com/wiki/evaluating.html)
- [V] **Long-document summarization faithfulness benchmarks** (adjacent, KB-construction faithfulness):
  - **FABLES** (arXiv 2404.01261): LLM raters of book-summary faithfulness do not correlate strongly with humans, and it gives a typology of **omission errors** [V abstract tail].
  - **BooookScore** (arXiv 2310.00785): *incremental updating* yields lower coherence but **higher detail than hierarchical merging** [V abstract tail]. This is the summarization analogue of the rewrite-versus-delta trade-off.
  - Older QA-based factual-consistency metrics are direct ancestors of probe-based wiki evaluation: **QAGS** (Wang, Cho, Lewis, arXiv 2004.04228, ACL 2020) [V] and **QuestEval** (Scialom et al., arXiv 2103.12693, EMNLP 2021) [V].
  - Sources: [FABLES](https://arxiv.org/abs/2404.01261); [BooookScore](https://arxiv.org/abs/2310.00785); [QAGS](https://arxiv.org/abs/2004.04228); [QuestEval](https://arxiv.org/abs/2103.12693)
- [V] **Streaming Knowledge Compilation** reports an LLM-as-judge confound for compiled-wiki QA on post-training knowledge. — [arXiv](https://arxiv.org/abs/2606.09877)

### Inferences
- For WiCER, the detail-level held-out failures (as opposed to whole-document failures) are what this literature predicts for an abstracted store. The best-supported mitigation pattern is **verbatim spans retained under the abstraction** (ReadAgent lookups, TierMem escalation, FlexA-Mem raw excerpts, LongMemEval K = V + fact). WiCER's own "verbatim render beats truncate" result fits this pattern.
- The memory-benchmark numbers in vendor papers (Mem0, Zep, Memori, True Memory, MIRIX) conflict by 20–30 points on the same LoCoMo split. Treat cross-paper LoCoMo comparisons as unreliable and cite MemoryAgentBench or LongMemEval ablations instead.

### Gaps
- I found **no dedicated benchmark for faithfulness of LLM-compiled knowledge bases or wikis** (unsupported-claim rate, omission rate of a compiled artifact against its corpus). The closest are long-summary faithfulness work (FABLES, BooookScore) and WiCER's own probe metric. AuthTrace (used by LLM-Wiki and WikiLoop) is a QA benchmark; I did not check its construction.
- MemoryAgentBench does not include A-MEM or Letta in its main table (per my fetch).

## Q4. Iterative self-refinement of a knowledge store with self-generated questions or tests, and generalization to unseen questions

### Takeaway
Question-driven repair works on the targeted questions. Evidence that it **generalizes to unseen questions is thin and mixed**. Intrinsic self-correction without external signal often fails. Self-evolving harness and memory loops show **overfitting to recent or update tasks, collapse of intermediate gains, and benchmark-shortcut exploitation**. The strongest existing safeguards are WikiLoop's guard penalty plus held-out Navigator, SEAGym's frozen validation plus held-out ID/OOD views, and incremental deltas rather than full rewrites (ACE). Sleep-time compute's finding that gains track **query predictability** suggests generalization from probes depends on how representative the probe distribution is of real queries.

### Cited Findings
- [V] **Self-Refine**, Madaan et al., arXiv 2303.17651 (NeurIPS 2023). Same-model feedback and refinement gives about +20% absolute on average across 7 tasks. — [arXiv](https://arxiv.org/abs/2303.17651)
- [V] **Reflexion**, Shinn et al., arXiv 2303.11366 (NeurIPS 2023). Verbal reflections stored in episodic memory. HumanEval pass@1 91%. Relies on external feedback such as unit tests. — [arXiv](https://arxiv.org/abs/2303.11366)
- [V] **Large Language Models Cannot Self-Correct Reasoning Yet**, J. Huang, X. Chen, Mishra et al., arXiv 2310.01798 (ICLR 2024). Without external feedback, self-correction fails and sometimes *degrades* performance. Implication for WiCER: probes must be checked against the **source corpus** (external signal), not against the wiki itself. — [arXiv](https://arxiv.org/abs/2310.01798)
- [V] **QAGS** and **QuestEval** (see Q3): asking questions of both source and summary and comparing the answers is an established faithfulness test. WiCER's probe evaluation is a repair-loop version of QAGS. — [QAGS](https://arxiv.org/abs/2004.04228); [QuestEval](https://arxiv.org/abs/2103.12693)
- [V] **ACE**: iterative full rewriting causes "context collapse". Incremental curated deltas prevent it and work "without labeled supervision" using execution feedback. — [arXiv](https://arxiv.org/abs/2510.04618)
- [V] **SEAGym: An Evaluation Environment for Self-Evolving LLM Agents**, Zheng et al., arXiv 2606.17546 (2026). Compares ACE, TF-GRPO and AHE with frozen update-validation and held-out ID/OOD views. Finds that "**frequent updates may fail to improve held-out performance, useful intermediate snapshots may collapse later**", and that source diversity and backend affect reliability. Direct evidence of the probe-overfitting risk for self-edited memory or context. — [arXiv](https://arxiv.org/abs/2606.17546)
- [V] **Bad Genius / CHASE**, G. Zhu et al., arXiv 2609.18366 (2026). Automatic harness optimization (editing prompts, memory, retrieval, tools) on a released benchmark can find **benchmark-wide shortcuts**. Task holdout alone does not catch them. Proposes counterfactual protocol transformations plus a held-out confirmation set. — [arXiv](https://arxiv.org/abs/2609.18366)
- [V] **WikiLoop**: the edit reward is downstream utility on target queries **minus a guard penalty for regressions on unrelated queries**. Learned edits **transfer to a held-out Navigator**. It also improves over LLM-Wiki on HotpotQA and MuSiQue without dataset-specific training. — [arXiv](https://arxiv.org/abs/2607.26604)
- [V] **LLM-Wiki Error Book**: persistent self-correction records reused across queries. The abstract gives no separate held-out analysis. — [arXiv](https://arxiv.org/abs/2605.25480)
- [V] **Sleep-time compute**: benefit is well correlated with how predictable user queries are from the context. Amortization works across *related* queries. — [arXiv](https://arxiv.org/abs/2504.13171)
- [V] **Nemori** (prediction-error-driven distillation) and **TierMem** (write back verified findings linked to raw sources) are two alternatives to probe-pinning for deciding what gets added to the store. — [Nemori](https://arxiv.org/abs/2508.03341); [TierMem](https://arxiv.org/abs/2602.17913)
- [V] **Dynamic Cheatsheet** and **ReasoningBank** improve on *later* test questions using memory built from earlier ones (online test-time learning), but in procedural domains (math, web tasks), not fact recall. — [DC](https://arxiv.org/abs/2504.07952); [ReasoningBank](https://arxiv.org/abs/2509.25140)
- [V] **Active Reading** and **SEAL**: self-generated questions and restatements improve recall of *unseen* benchmark questions about the same documents (66% SimpleQA-Wiki subset). This is evidence that self-generated study material generalizes, at least when it is broad and plentiful rather than a small probe set. — [Active Reading](https://arxiv.org/abs/2508.09494); [SEAL](https://arxiv.org/abs/2506.10943)

### Inferences
- In a fixed token budget, probe-driven pinning is zero-sum. Repairs that fix probe-hit facts can displace unprobed facts. This is the WiCER held-out pattern, and SEAGym's "updates fail to improve held-out" result fits it. Mitigations with literature support:
  - a guard or held-out probe split with regression penalties (WikiLoop, SEAGym, CHASE);
  - delta edits instead of recompiling from scratch (ACE);
  - more and broader self-generated questions (the Active Reading and SEAL scale argument);
  - raw-span fallback (TierMem, ReadAgent).
- Without external grounding, intrinsic self-correction is unreliable (Huang et al.). WiCER's design of checking probes against the source corpus is the right side of that line. The weak link is the judge: Streaming Knowledge Compilation reports judge confounds.

### Gaps
- I found **no paper that directly measures probe-to-held-out generalization for a compiled text knowledge store** with a clean split, as in WiCER's own held-out analysis. WikiLoop is closest, but it uses RL-learned edits and a navigation reader, not in-context reading.
- I did not read SEAGym's or WikiLoop's quantitative held-out results; only the abstracts.
- No systematic study found of *how many* self-generated probes are needed before gains transfer to unseen questions.

### Synthesis: design patterns relevant to WiCER (cross-question; derived from the cited items above)
1. **Write**: there are three families.
   - Extract atomic facts: Mem0, Memory-R1, Memori, Schema-Grounded.
   - Write notes or pages with links: A-MEM, LLM-Wiki, TrajWiki, Karpathy.
   - Keep verbatim units with provenance: True Memory, FlexA-Mem, EDU memory, TierMem's raw tier, ReadAgent pages.

   The 2026 trend is to separate an **immutable verbatim layer** from a **derived navigational layer**.
2. **Consolidate/update**:
   - LLM-adjudicated ADD/UPDATE/DELETE/NOOP: Mem0, Memory-R1.
   - Rewriting attributes of linked notes: A-MEM "evolution".
   - Tiered promotion: MemoryOS, MemGPT.
   - Offline sleep-time rewriting: Letta sleep-time, LightMem.
   - Prediction-error gating: Nemori.
   - Claim-level REVISE/DEPRECATE with immutable snapshots: TrajWiki.
   - Incremental curated deltas: ACE.

   Full recursive rewriting (recursive summarization) is the design most clearly linked to detail loss ("context collapse"; BooookScore's incremental-vs-hierarchical trade-off).
3. **Forget**: deleting stale facts (Mem0) competes with never deleting and timestamping instead (THEANINE, Zep bi-temporal, TrajWiki DEPRECATE). Selective forgetting is the weakest competency in MemoryAgentBench (≤28% multi-hop).
4. **Link**: Zettelkasten links (A-MEM), bidirectional wiki links (LLM-Wiki, Karpathy), temporal KGs (Zep), and timelines (THEANINE). Links help navigation agents. For a small in-context reader, the benefit of links is untested in what I found.
5. **Verbatim vs abstracted**: abstraction wins on tokens and on multi-session aggregation. Raw storage wins on detail recall (LongMemEval value ablation, MemoryAgentBench AR, Bricks, TierMem, FlexA-Mem). The best-supported hybrid is an **abstracted key or index plus a verbatim value** (LongMemEval K = V + fact; ReadAgent gist + lookup).
6. **Feedback loops**: question-driven repair (WiCER, LLM-Wiki Error Book, DeepRefine, WikiLoop) needs an external grounding signal (Huang et al.) and a held-out guard (WikiLoop, SEAGym, CHASE) to avoid overfitting to probes.
